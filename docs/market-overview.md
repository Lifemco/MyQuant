# A股市场总览

入口为导航 **市场总览**（`/market`）。读取页面仅加载缓存；点击 **刷新市场数据** 启动后台任务，页面轮询任务状态。离开页面不停止后台采集；后端退出则任务停止，下次可重新启动。重复点击、多个页面或服务进程使用同一采集锁，不会同时启动重复任务。

## 全市场宽度采集

1. 先刷新市场数据，获取全量A股名单；名单超过24小时需重新刷新。
2. 点击 **构建 / 更新全市场宽度**。首次逐只采集，可能耗时较长；任务进度和失败只数可见。按25只检查点更新曲线，连续5只失败会提前停止，避免持续请求不可达源。
3. 每只成功返回的历史单独原子保存，同一已收盘目标日重试复用成功文件。隔日重新获取完整前复权窗口，避免把两次复权基准直接拼接。

此图使用最近一次名单回溯，存在幸存者偏差；北交所尚未纳入。采集覆盖数与每日MA有效数分别披露：新上市、停牌、缺数均会影响分母，不能把不完整样本称为完整市场。当采集不足时标记部分数据，不做缺数补零。

## 接口、缓存和修改

- `GET /api/market/overview`：即时读取六个统计区块和任务状态，不发出外部请求。
- `POST /api/market/refresh`：启动指数/行业/全量快照/风格/估值后台刷新，返回缓存与任务状态。
- `POST /api/market/breadth`：启动全市场历史采集；缺少或过期名单返回422。
- 外部SDK入口、参数/字段映射、超时、指数代码全部在 `backend/app/data/third_party.py`；业务模块仅做统计与存储。SDK内部地址变更的边界同第三方接口说明。
- 缓存为独立 `data/market/`，JSON/Parquet及锁均不提交GitHub，不修改自选股、策略数据或行情监控缓存。
- 各图区块独立更新；采集失败保留旧成功数据并标记缓存状态。抓取超过24小时或历史行情日期距今超过7个自然日会标记待更新（保守提示，不等同于交易日历判定）。后台进程异常停止时，页面提示重新刷新。
- 估值调用在有总超时的独立进程执行，返回后回收进程，避免SDK内JS运行时的退出钩子阻塞主服务。

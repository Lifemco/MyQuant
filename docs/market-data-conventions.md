# 行情口径与同日数据核对

同一标的、同一交易日的完整收盘、不复权价量应可核对，但不能直接将不同接口的返回表拼接。

## 已实现的接入规则

- **完整标的身份**：保存市场、交易所代码、类型及价格单位。`cn/000001` 表示深交所平安银行，`cn/sh000001` 表示上证指数，缓存文件分开。沪深京常见指数保留明确交易所前缀；股票前缀须与代码匹配。港美市场仍使用现有股票代码规则。
- **记录来源与时间**：Parquet attrs 的 `marketData` 保存底层来源、价格复权、原始成交量单位、币种、时区、采集/观察时间及已确认截止日期，API和页面可查看。`source`应填写底层数据商；通过AKShare访问腾讯时，底层来源仍是`tencent`，不能算独立数据源对账。
- **不猜测单位**：当前腾讯A股量按手（100股）记录，港股及Yahoo股票量按股记录。保留原单位，页面明确标记；跨源核对再统一换算成股。未知单位不进行比较或拼接，不将港股一手固定假设为100股。
- **复权单独识别**：腾讯返回qfq数据标记前复权；如果退回原始K线，标记不复权。Yahoo自动调整价单独标记，不冒充同算法的腾讯前复权。同一缓存不能静默改变复权方法。
- **只比较已确认收盘的日线**：跨源核对要求双方均为不复权日线，只比较共同的已确认日期。盘中采集的缓存不会因为服务器时间到了晚上就自动升级为收盘数据，必须取得新的数据或符合要求的快照。
- **成交事实与计算字段分开**：核对开、高、低、收及统一单位后的成交量；涨跌幅、换手率、市值等不作为同一交易事实强制相等。价格绝对误差容忍`0.0001`，成交量换算后的容忍`0.000001`股，超过阈值列出差异，不自动平均或覆盖。
- **换源不自动拼接**：来源、身份、周期、复权或成交量单位不同即拒绝覆盖现有缓存。需要先独立获取数据核对，再明确重建。相同来源的数据才能按已有的复权修订规则备份/重建。没有共同日期时也不能报告核对成功。
- **旧缓存可读但不假定可信口径**：原有样例不修改，页面显示口径未确认。第一次用带元信息的新数据刷新时，先备份旧文件，再重建当前返回窗口；不把未知旧数据和新数据混用。带口径缓存不能被缺少元信息的新数据降级覆盖。
- **盘中快照有边界**：未知或其他来源缓存不混入腾讯快照。腾讯前复权数据要求基准当天取得且昨收能对齐，再合成当天K线；快照交易时间用于判断该根K线是否已确认收盘。
- **异常数据拒收**：缺失/无穷值、负成交量、不合法的开高低收关系、同日期冲突数据均不静默写入。报价按返回的真实交易所代码匹配，不依赖返回顺序。

## 使用与范围

`app.data.contract.compareDailyBars(left, right)`返回共同日期数、差异字段和是否来自同一底层来源。输入表需要由`describeBars`附带清楚的元信息；它只在单位明确时换算，不自动判断两套前复权价是否同基准。

已新增AKShare/BaoStock下载适配器，沿用相同元信息和校验流程。第三方接入统一在 `backend/app/data/third_party.py` 管理，使用方式见 `third-party-interfaces.md`。

真实行情连接仍受本任务云环境白名单限制。以上自动检查使用固定数据验证规则，不代表已经取得腾讯、AKShare、BaoStock三方的同日实测行情。网络放行后应再进行实际样本对账，详见 `live-market-verification.md`。
